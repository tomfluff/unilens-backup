# Add Formatters

## Context

The project spans a Python backend and two TypeScript libraries (`unilens-lib`, `accessibility-lib`). Before this ADR, there was no consistent way to run all formatters together.

## Decision

Add a unified `make format` target at the root that runs formatters for every sub-project in sequence:

1. **Backend** (`backend/`) — runs [Black](https://black.readthedocs.io/) on `app.py` inside the virtualenv.
2. **JS targets** (`unilens-lib/`, `accessibility-lib/`) — runs [Biome](https://biomejs.dev/) (`biome format --write`) on each library's `src/` directory.

The root `Makefile` delegates via two sub-targets:

- `format-backend` → `cd backend && make format`
- `format-all` → iterates `JS_TARGETS` (defined in `make-targets.mk`) and calls `make format-target` for each.

Each individual library Makefile exposes its own `format` target, so targets remain independently runnable.

## Consequences

- A single `make format` from the repo root formats all code uniformly.
- Adding a new JS library only requires appending it to `JS_TARGETS` in `make-targets.mk`.
- Formatter choices (Black for Python, Biome for TypeScript) are enforced per-ecosystem without cross-contamination.

## Choice of JS Formatter

There are a lot of different JS formatters out there. We opted with `biome` since it runs both linting and formatting (i.e. does basic static analysis + handles code format), based on [this link](https://dev.to/rjonmshka/the-two-tool-problem-eslint-prettier-and-the-case-for-a-unified-toolchain-3ene#:~:text=The%20solution%20the%20community%20landed%20on%20is,fully%20surrenders%20the%20formatting%20territory%20to%20Prettier.).
